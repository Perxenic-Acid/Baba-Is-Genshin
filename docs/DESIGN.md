# RuleWorld 设计依据

本文件依据用户于 2026-10-26 补充的两份历史讨论整理。用户的明确要求与
后续修订优先于历史助手建议。历史记录中的平台能力调查不是当前 API 保证。

## 已确认的工程方向

- 作品的实际宿主是千星奇域 UGC 关卡存档。本地脚本通过编辑器映射、挂载、
  跨脚本 Invoke 运行；不可假定游戏支持普通 require、文件 I/O 或网络访问。
- 当前建设规则世界的基础设施。BABA、YOU、IS、WIN 及默认语序都属于建立
  在框架上的玩法配置，不应成为世界内核公理。
- 逻辑状态、语言、语义、状态转移与表现层分开。当前使用原生 UI；未来 3D
  只替换前端，不由动画、控件或物理碰撞决定游戏事实。
- Reader 提取空间符号，Parser 生成 AST，语义层降低为 Rule IR/行为定义。
  这些边界不能合并；当前横向/纵向读取与 IS 语法是初始实现。
- 行为可以产生意图、约束和操作计划，不能直接修改共享世界。
- 优先验证最少公理和具体闭环，按需要扩展，不预建任意维空间或通用语言。

## 世界与状态转移约束

1. 实体 ID 独立于名称、类型、坐标和外观。
2. 所有影响后续计算的可变状态必须可完整保存和恢复；未来随机状态也一样。
3. 一格容纳多个实体，空间占据关系与实体身份分离。
4. 规则可以来自空间文字、关卡配置及默认来源；TEXT IS PUSH 是规则来源，
   不是 Text 实例硬编码的内蕴 PUSH。
5. 世界只能经过校验后的原子状态转移改变。同一状态、输入与配置应得到
   相同结果；错误不产生半回合，Undo 恢复整步。
6. 表现层读取世界与差异，不决定世界事实。

M9.3D 将 Text 建模为 Object 子类，独立保存 Text.name。M9.3E 为所有
Object/Text 增加 direction：Left、Up、Right、Down、Mid、None。方向是
内蕴状态，规则投影与 IS 类型转换不应丢失它。

## 已确认的关卡包设计需求

- 宏观按旅途组织，拓扑改编提瓦特；局部谜题保持机制与教学质量。
- 目标难度接近或高于官方标准关卡包；较早引入更多 Meta，但尚未确定数量。
- 更多使用知识锁，允许重访已通关关卡并发现另一个有意义的结果；条件锁
  可以承担节奏控制，不要求彻底取消。
- 子关卡与子地图在设计抽象中统一：关卡内部可以包含其他关卡。提瓦特
  本身也有对象、规则与 Meta，而非外部选关菜单。
- 七天神像本身是承担教学任务的关卡，内部包含子关卡；不必都有常规 WIN。
  后续讨论明确：完成其内部第一关揭示地区地图。
- 可见性、可达性、可解性分开建模，不把隐藏显示自动等同于禁止通行。
- 允许地区推进条件，例如蒙德五张地图至少三张达到各自通关及格线。
  具体关卡数、及格阈值仍需设计，不把助手示例值当作既定参数。
- 天空岛作为根关卡是用户提出的可能方案，尚非冻结决定。
- ROCKET IS WIN 与另一处 Meta 产生可控对象、在提瓦特汇合进入霜月，属于
  需要未来架构承载的设计案例；具体跨层转移协议和胜利语义尚未实现。

## 不可把历史设想当成已实现能力

可替换语法/行为注册、完整阶段配置、创建/删除、嵌套关卡、跨层原子变更、
进度持久化、迷雾与条件锁目前都不能由方向和 IS 转换的成功直接推导出来。
每项需要独立规格、自测和相应的真机验证。

## 2026-10-27 用户修订：关卡选择与退出

- SELECT 与 YOU 是两个独立属性；只有 SELECT 对象能选择关卡，不能按
  Avatar 外观、YOU 属性或实体 1 判断选择资格。
- 关卡进入需要独立确认，不能踩格自动进入。用户最新澄清使用 F 交互即可，
  不要求物理 Enter；F 绑定独立确认动作。
- 退出形式包括内部指向父级的关卡块、获胜、当前关卡转换。
- 撤销必须恢复关卡切换与完整上下文，不能跨越未记入历史的导航事件。
- 后续实现语义时持续核对本机 Baba Is You/Data 原版脚本，不能靠印象补规则。
