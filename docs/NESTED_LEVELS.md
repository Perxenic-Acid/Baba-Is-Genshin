# M9.3K：嵌套实例与可操作测试

## 权威接口

world.lua 新增纯数据实例树接口，继续使用现有八个脚本映射。

- RW_CreateLevelTree(definitions, root_definition_id)：复制校验过的定义目录，
  创建 instance:1 根实例。普通谜题和地图没有类型分支。
- RW_GetActiveLevel(tree)：读取当前 session（按快照只读约定使用）。
- RW_UpdateActiveLevel(tree, session)：接回当前实例的 Commit/Undo 结果，
  校验实例与定义身份一致。session 须来自可信的实例/Commit/Undo 接口，
  不是导入或任意存档反序列化入口。
- RW_EnterLevel(tree, slot, definition_id)：以父实例 ID + slot 唯一绑定子实例。
  首次创建；再次进入复用完整世界、分配器和历史。不同父实例下的同名 slot
  不共享实例，同一 slot 不允许换定义。实例序号由树内分配器确定性递增。
- RW_ReturnLevel(tree)：恢复栈顶父实例，保留所有子实例；根节点返回 at_root。

返回新树或 nil/reason；失败不修改输入树。树与 session 共享不可变旧快照，
调用方不得原地改动。进入/返回本身不写任何局部世界，也不消耗移动回合。

Z 的范围明确为当前实例自己的历史；空历史不返回父级。
导航栈不是历史栈。移动到入口的那一步仍记入原实例的局部历史；跨层统一
事务/Undo 尚未实现。退出再进入会保留站在 OUT 上的位置，不会立即自动退出；
必须先离开再踏入 OUT。重新启动试玩会重新构建整棵树，不跨启动保存。

## 当前真机测试棋盘

原棋盘保留原有默认规则、箱子与文字。新增紫色背景入口：
根地图 A=(2,1)、B=(1,2)，子实例 OUT=(2,1)。标题显示 MAP/PUZZLE 和实例 ID。
A/B 使用同一份关卡定义，却有独立运行状态。渲染只是显示导航提示，
导航的权威状态在实例树。原生宿主示例检测实体 1 实际移入入口格；
这是明确的测试交互，不是语言中的 ENTER 属性，也不属于移动求解器。
后台 API 支持任意深度，当前可视样例为根+子两层。

从刚启动试玩开始按以下步骤验证（W 上、A 左、S 下、D 右）：

1. W：进入 A。标题由 MAP 变 PUZZLE，实例 ID 改变，Turns=0。
2. D：推动两箱，箱子由 x=3/4 移到 x=4/5。
3. W、A：踩 OUT 返回根。根玩家仍在 A 入口 (2,1)，根的箱子没动。
4. S、W：再次进入 A，实例 ID 不变、箱子仍在 x=4/5，玩家仍在 OUT。
5. Z：只撤销 A 的最后一步，玩家从 OUT 回到 (3,1)，仍留在 A；再 A 返回。
6. A、S：从根的 (2,1) 经 (1,1) 踩 B，进入另一实例。箱子仍在初始 x=3/4，
   Turns=0。Z 应报告 empty_history，不返回根；W 才踩 OUT 返回。

入口可能被玩家覆盖显示，但移开后标签仍在。无需新增键位或编辑器映射。
